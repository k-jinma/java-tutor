# レビューの観点

上から順に、学習効果とほかの問題への波及が大きいもの。すべてを指摘する必要はない。プロジェクトに実際にあるものだけを拾う。

## 1. 動かない・壊れている

- コンパイルエラー
- 実際のバグ。再現手順（どのメニューをどの順に選ぶか）を書けるもの
- 例外で落ちる入力（範囲外の番号、数字以外の入力など）。初学者向けには、優先度を下げて1つにまとめる

## 2. 継承とポリモーフィズム

- is-a が成り立たない継承（「A は B の一種である」と言えるか）
- 親クラスが `instanceof` で子クラスを判定している（親が子に依存）
- 状態の変化を「別クラスのオブジェクトに作り直す」ことで表している
- インターフェースに、一部の実装しか使わないメソッドがある（`return null` だけの実装）
- インターフェースにないメソッドを、呼び出し側が具体クラス名で呼んでいる

## 3. 責務とクラス分け

- 1つのクラスが複数の種類の仕事をしている（変更する理由が複数ある）
- ある情報を持つべきクラスが別にある（例：料金はランクが持つ、日数は貸出が持つ）
- 現実の概念に対応するクラスが欠けている（例：貸出伝票）
- 同じ情報が2か所にあり、食い違う可能性がある（フラグとクラスの種類、コピーした値）

## 4. カプセル化

- getter が内部の可変リストをそのまま返し、外側で `add` や `remove` をしている
- `public` や不要な `protected` のフィールド
- 同じチェックが複数の場所に散らばっている

## 5. 入出力とロジックの分離

- 計算や状態変更のメソッドの中で `System.out` を使っている
- `Scanner(System.in)` が複数作られている、使われていない

## 6. 値の表し方

- 決まった数種類の値を `int` や `String` で表している（enum 候補）
- 配列の添字と意味の対応が暗黙の約束になっている
- 不正な値でオブジェクトが中途半端に作られる（コンストラクタで例外を投げていない）
- 意味が逆に読める boolean（`rented = true` が「借りられていない」など）

## 7. 命名とパッケージ

- 名前と中身が合わないメソッド（`setXxx` なのに加算している、など）
- Java の命名の習慣（クラスは大文字、パッケージは小文字、メソッドは小文字）
- パッケージ名とクラス名が同じ、置き場所がおかしいクラス
- ローマ字と英語の混在、タイポ
- ソース以外のもの（メモ用のクラス、`bin/` の `.class` が git 管理下にある）
